# История изменений 1C-telemetry


## 1.0.2-dev-r1 · TEST · 20.11.2026

- Настроены контролируемые свойства основного языка и режима интерфейса для целевой тестовой базы. Дополнения заимствуют только стандартный русский язык, режим интерфейса `TaxiEnableVersion8_2`.
- Контролируемые свойства и идентификатор языка совпали с установленным расширением. Собран новый полный комплект. [Актуальные ZIP](README.md) · [Отчёт приёмки](docs/ACCEPTANCE.md).

## 1.0.1-dev-r1 · TEST · 20.11.2026

- Исправлена ошибка XDTO при импорте: `Copyright` в обоих расширениях и в образце регламентного задания записывается как `LocalStringType`. Синхронизированы версии и индексы.
- Добавлен регрессионный тест для формата `Copyright`. Проверка поля по XSD и структурная проверка прошли. [Актуальные ZIP](README.md) · [Отчёт приёмки](docs/ACCEPTANCE.md).

## 1.0.0-dev-r1 · TEST · 20.11.2026

- `ТЛМ_Сервер`: три маршрута HTTPS, индивидуальные токены с SHA-256 и отзывом, регистры исходного JSON и файлов, временная запись и фиксация. Время приёма хранится в UTC.
- `ТЛМ_Клиент`: отправка готового JSON и файла одним POST, ping, системное/PEM-доверие, единая структура из шести полей.
- Русская штатная справка, отдельные роли, примеры BSL, штатного задания, PowerShell, Python и cURL.
- Детерминированная сборка ZIP32, SHA-256 и опись исходных деревьев. Оба ZIP проверены на Windows. Примеры Python/cURL проверены на отдельном HTTPS-обработчике. Общие модули синтаксически проверены на учебной 1С 8.3.27.1508.
- Целевая установка и E2E ожидаются. [Проверенные ZIP на главной](README.md) · [Отчёт с точными SHA и проверками](docs/ACCEPTANCE.md).

## Unreleased — 18.11.2026
- Согласован испытательный контур: существующая тестовая ИБ, HTTPS-публикация Apache, удалённая Windows-станция для HTTP-тестов. Администратор устанавливает сервер из ZIP; разработчик сверяет реальные записи и файлы. Клиент BSL/расписание проверяются отдельно. Поставка заказчику — только полные исходные ZIP и примеры, без CFE. Добавлен TEST-PLAN.md; испытания ещё NOT_RUN.
- Уточнение владельца: только прямой POST файла, без блочной передачи, отдельного регистра загрузок, дополнительных маршрутов или автоматических повторов. Заказчик самостоятельно делит большие файлы при необходимости. Контракт результата упрощён до шести полей. Предыдущая проектная идея блоковой передачи отменена до реализации.
- Убран конфигурационный предел общего размера файла. Первоначально предложена блочная передача 2–3 ГиБ (отменена следующим уточнением); простой POST сохранён. Зафиксирован контракт структурированных результатов BSL и HTTP ошибок, включая неопределённый исход и идемпотентность блоков. Реализация/приёмка пока NOT_RUN.
- Инициализация проекта, описание архитектуры, ТЗ, API v1, правила разработки, безопасности, авторства и выпуска ZIP.
- Проектируемые функции: два расширения, хранение неизменённого JSON и файлов, X-Token, HTTPS, примеры скриптов, штатное расписание заказчика.
- Реализация, сборка ZIP/CFE, BSL LS, CheckConfig, установка и E2E: NOT_RUN / NOT_IMPLEMENTED. Релизов нет.

При каждом выпуске добавлять в начало новый раздел (дата, версии обоих расширений, изменения, точные ссылки на ZIP и хеши, результаты проверок и ограничения). Не переписывать старые релизы.
