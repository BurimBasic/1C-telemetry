# 1C-telemetry — обязательные правила для разработчиков и агентов

Перед работой читать README, CHANGELOG, docs/SPECIFICATION.md, docs/API.md, docs/CODE-DOCUMENTATION-STANDARD.md, docs/RELEASE-RUNBOOK.md и SECURITY.md. Применены общие нормы OFFICE20 без переноса его инфраструктуры, MCP, DDL, Gateway, секретов и прикладных данных.

1. Если поручена реализация — выполнить её в репозитории, не подменять планом/Issue/TODO. Исключение — прямо запрошенная документация/исследование. Сначала текущий main/открытые PR/точные SHA, затем минимальное подтверждённое решение. Не размножать задачи. Не ждать указания продолжить независимые разрешённые шаги.
2. Ветка от свежего main, один заявленный компонент (клиент/сервер/примеры/CI/документация); общий контракт двух сторон — явно указать в PR. Адресные тесты, тестовая установка, позитивная/негативная приёмка, PR в main, owner review и merge. Не обходить защиту ветки. Не менять чужие компоненты и базы.
3. Проверять BSL через BSL Language Server/доступные справочники и инструменты платформы; статический анализ не заменяет CheckConfig. Перечень APIs и контекст выполнения подтверждать по help установленной версии, использовать нативную проверку 1С при наличии. Фиксировать точный SHA, версию платформы, тесты, результаты и ограничения.
4. Все исходники на русском языке документированы; copyright в начале/конце, Comment/Copyright метаданных обоих расширений. Машинная проверка стандартов обязательна. Не коммитить секреты, реальные JSON клиентов, закрытые ключи, выгрузки, логи с данными. Публичный репозиторий: никаких приватных инфраструктурных деталей.
5. Не создавать пользовательских форм/обработок/оболочки, планировщика, Gateway, зависимости от БСП. Константы ТЛМ_, штатные регистры и справочник. Не менять спецификацию молча.
6. Каждый runtime XML/BSL diff после выданного ZIP — новый уникальный build; версии синхронны с метаданными, VERSION, BUILD_STATUS.json и экспортной версией модуля. Полный исходный ZIP из exact SHA, не патч, не CFE. r2 — только перепаковка идентичных исходников. Следовать RELEASE-RUNBOOK; никаких CP866/ZIP64/неверных ссылок.
7. **Обязанность при каждой поставке:** актуализировать README (главная страница), CHANGELOG (не стирать историю), ссылки на последние релизы/ZIP обоих компонентов, описание функций, ограничения/проверки/установку. Обязательно выдать владельцу проверенную неизменяемую ссылку на каждый актуальный ZIP и манифест/sha256; при отсутствии релиза явно сообщить. Не ссылаться на истекающий artifact как на постоянный релиз.
8. CI локальный/адресный, полный release gate по точному SHA. Только авторизованные runner/ресурсы; не подключать приватный runner к публичному репозиторию без отдельного разрешения, не запускать платный CI или автодеплой. NOT_RUN, FAIL, BLOCKED не являются PASS. Тестовый ZIP может быть выдан по запросу с честным статусом.
9. Отчёт разработчика: IMPLEMENTED (commit/PR, фактическое поведение), TESTED (SHA, набор, Run ID, PASS/FAIL/NOT_RUN), RELEASE (точные ссылки, хеши), REMAINING, BLOCKED. Исходники, ZIP, проверенный CFE, установленная версия — разные состояния. Не выполнять production deploy без отдельного разрешения, backup и rollback.
