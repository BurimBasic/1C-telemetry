# Правила разработки 1C-telemetry

Обязательны AGENTS.md, [стандарт документации](docs/CODE-DOCUMENTATION-STANDARD.md), [ZIP-регламент](docs/RELEASE-RUNBOOK.md), SECURITY.md. Новая ветка от свежего main; при наличии существующего PR продолжить его. Сначала тестовый контур, адресные проверки, PR, owner review, затем main и immutable release. Не считать изменения README выпуском новой функциональности. Не использовать force push и не ослаблять упавшие тесты.

Перед PR: проверить XML/BSL, комментарии/авторство, версии/манифест, отсутствие секретов, контракт API, негативные тесты и совместимость, безопасный откат. Для security/auth/FS/TLS — полный применимый набор отрицательных тестов. Локальный тест, BSL LS, native CheckConfig, проверка импорта и E2E — отдельные свидетельства. При недоступности нативной среды фиксировать NOT_RUN; stable release не принимать без проверок. Гарантии функций только на испытанной матрице. Для публичного repo — синтетические данные и обезличенные логи. Обновить README и CHANGELOG в той же поставке; указать точные файлы/изменения и ссылку на последний релиз.

Нормы адаптированы из стандартов OFFICE20: AGENTS, CONTRIBUTING, CODE-DOCUMENTATION-STANDARD, ZIP RELEASE RUNBOOK, PR ACCEPTANCE WORKFLOW и CFE BUILD HANDOFF, без внутренней инфраструктуры исходного проекта.
