# 1C-telemetry

**Приём JSON и файлов из 1С и скриптов в одну базу 1С.** Отправитель передаёт данные по HTTPS. Сервер определяет клиента по токену, записывает JSON в регистр и сохраняет файлы на диске с исходными именами. UUID из ответа позволяет найти конкретную отправку.

- **Сервер** устанавливается в центральную базу и публикуется по HTTPS. Администратор управляет токенами, просматривает JSON и скачивает принятые файлы.
- **Клиент** устанавливается в базу-отправитель. В нём есть форма для ручной проверки и серверный BSL API для автоматизации. Публиковать базу-отправитель не требуется.
- **Внешние скрипты** обращаются к опубликованному серверу напрямую. На машине со скриптом 1С не нужна.

## Установка

### Сервер

1. Распакуйте серверный ZIP в пустую папку. В **Конфигурация → Расширения конфигурации** создайте дополнение `ТЛМ_Сервер`, откройте его и выполните **Загрузить конфигурацию из файлов**. Укажите папку с `Configuration.xml`, проверьте конфигурацию и обновите конфигурацию базы данных. При обновлении загружайте файлы в существующее расширение.
2. В «1С:Предприятии» назначьте администратору роль `ТЛМ_АдминистраторСервера`. В **Функциях для технического специалиста** найдите объекты по `ТЛМ_`. Откройте **ТЛМ_Каталог файлов телеметрии**. На Windows при пустом значении используется `C:\temp`. На Linux укажите абсолютный путь к существующему каталогу. Каталог должен быть вне корня веб-сайта и доступен процессу сервера 1С для записи.
3. В справочнике **ТЛМ_Клиенты телеметрии** создайте отдельную карточку для каждого отправителя. Задайте уникальный токен и включите **Приём разрешён**. Для блокировки клиента снимите этот флаг.
4. Опубликуйте HTTP-сервис `ТЛМ_ПриемДанных` по HTTPS. Если имя публикации `Telemetry`, базовый адрес для отправителя — `https://server.example/Telemetry/hs/telemetry`. В настройки вносится этот адрес целиком.

### Клиент

Загрузите клиентский ZIP в дополнение `ТЛМ_Клиент` тем же способом. Назначьте `ТЛМ_АдминистраторКлиента` пользователю, который настраивает и проверяет обмен. Для штатных серверных вызовов предусмотрена роль `ТЛМ_ОтправкаТелеметрии`. Найдите константы через **Функции для технического специалиста → Константы**, поиск `ТЛМ_`.

| Настройка | Значение |
|---|---|
| **ТЛМ_HTTPS-адрес сервера** | Например, `https://server.example/Telemetry/hs/telemetry` |
| **ТЛМ_Токен отправителя** | Исходный токен из карточки этой базы на сервере |
| **ТЛМ_Таймаут (сек.)** | `0` использует 60 секунд |
| **ТЛМ_Путь к сертификату** | Пусто для доверия ОС. Для частного УЦ укажите путь к доверенному публичному PEM, доступный процессу 1С |
| **ТЛМ_Использование авторизации на сервере телеметрии** | «Нет» для отдельной публикации с одним токеном. «Да», если публикация требует HTTP Basic |
| **ТЛМ_Имя пользователя сервера телеметрии** и **ТЛМ_Пароль пользователя сервера телеметрии** | Заполняются при включённом Basic |

## Проверка из 1С

1. В базе-отправителе откройте **ТЛМ_Клиент телеметрии → ТЛМ_Проверка телеметрии**. Эту же форму можно открыть через **Перейти по ссылке…** и `e1cib/app/Обработка.ТЛМ_ПроверкаТелеметрии`.
2. Нажмите **Проверить подключение**. Ожидаемый ответ — HTTP `200`. Проверка связи не создаёт записей в истории.
3. Вставьте в поле JSON, например `{"source":"test","value":42}`. Нажмите **Отправить JSON**. Ожидаемый ответ — HTTP `201` и UUID.
4. Нажмите **Выбрать файл**, выберите небольшой файл и нажмите **Отправить файл**. Ожидаемый ответ — HTTP `201` и другой UUID.
5. В центральной базе найдите UUID в регистрах **ТЛМ_Полученные JSON** и **ТЛМ_Полученные файлы**. Сверьте отправителя и содержимое. Чтобы получить файл, выделите строку и нажмите **ТЛМ_Скачать файл**. Колонка **Путь к файлу** показывает путь относительно каталога приёма.

Новые файлы на диске лежат по схеме `<каталог приёма>/<UUID>/<исходное имя>`. Одинаковые имена можно отправлять повторно. Каждая успешная отправка создаёт собственную запись. В форме проверки файл сначала передаётся из браузера или тонкого клиента в базу-отправитель.

## Методы клиента 1С

Вызывайте методы общего модуля `ТЛМ_Клиент` из серверного BSL. Все параметры соединения берутся из констант базы-отправителя.

| Метод | Что передать | Что получить |
|---|---|---|
| `Версия()` | Без параметров | Строку версии модуля |
| `ПроверитьПодключение()` | Без параметров | Результат проверки, при успехе HTTP 200 |
| `ОтправитьJSON(ТекстJSON)` | Готовый JSON строкой | При успехе HTTP 201 и UUID записи |
| `ОтправитьФайл(ПутьКФайлу)` | Путь к файлу, доступный с сервера 1С | При успехе HTTP 201 и UUID записи |

```bsl
// Выполняется на сервере 1С.
Сообщить("Версия клиента " + ТЛМ_Клиент.Версия());

Связь = ТЛМ_Клиент.ПроверитьПодключение();
Если Не Связь.Успех Тогда
    Сообщить(Связь.КодОшибки + " " + Связь.ОписаниеОшибки);
Иначе
    JSON = ТЛМ_Клиент.ОтправитьJSON("{""source"":""1c"",""value"":42}");
    Если JSON.Успех Тогда
        Сообщить("UUID JSON " + JSON.Идентификатор);
    Иначе
        Сообщить(JSON.Состояние + " " + JSON.ОписаниеОшибки);
    КонецЕсли;

    Файл = ТЛМ_Клиент.ОтправитьФайл("D:\Telemetry\report.log");
    Если Файл.Успех Тогда
        Сообщить("UUID файла " + Файл.Идентификатор);
    Иначе
        Сообщить(Файл.Состояние + " " + Файл.ОписаниеОшибки);
    КонецЕсли;
КонецЕсли;
```

Методы обмена возвращают структуру с полями `Успех`, `КодHTTP`, `Идентификатор`, `КодОшибки`, `ОписаниеОшибки` и `Состояние`. Сначала проверяйте `Успех`. При состоянии `НЕИЗВЕСТНО` проверьте регистр приёмника перед повтором отправки. Код можно вызывать из своего регламентного задания. [Обработка результатов и ошибок](docs/TRANSFER-AND-ERRORS.md) · [Пример расписания](examples/README.md#штатное-регламентное-задание).

## PowerShell

### Готовый скрипт

Распакуйте архив примеров и откройте PowerShell в его корне. [Скачать Send-Telemetry.ps1](https://github.com/BurimBasic/1C-telemetry/raw/2bccff105b9b4bac9d666f8bfb37b39b332859a6/examples/powershell/Send-Telemetry.ps1).

```powershell
$env:TLM_URL = 'https://server.example/Telemetry/hs/telemetry'
$env:TLM_TOKEN = Read-Host 'Токен из карточки клиента'

.\powershell\Send-Telemetry.ps1 -Mode ping
.\powershell\Send-Telemetry.ps1 -Mode json -Path 'C:\Telemetry\report.json'
.\powershell\Send-Telemetry.ps1 -Mode file -Path 'C:\Telemetry\report.log'
```

Готовый скрипт рассчитан на публикацию с одним токеном. Для JSON из файла используйте UTF-8 без BOM. Скрипт возвращает `Http` и `Id`. Ниже — вариант для собственного скрипта, который можно использовать и с Basic.

### Написать свой скрипт

Пример работает в Windows PowerShell 5.1 и PowerShell 7. Замените адрес и путь к файлу. Для публикации с Basic установите `$useBasic = $true` и введите учётные данные публикации. Для публикации с одним токеном оставьте `$false`.

```powershell
$ErrorActionPreference = 'Stop'
$base = 'https://server.example/Telemetry/hs/telemetry'.TrimEnd('/')
$token = Read-Host 'Токен из карточки клиента'
$encodedToken = [Uri]::EscapeDataString($token)
$encodedToken = $encodedToken.Replace('!', '%21').Replace("'", '%27').Replace('(', '%28')
$encodedToken = $encodedToken.Replace(')', '%29').Replace('*', '%2A').Replace('%7E', '~')
$headers = @{ 'X-Token' = $encodedToken; Accept = 'application/json' }

$useBasic = $false
if ($useBasic) {
    $credential = Get-Credential -Message 'Пользователь публикации 1С'
    if ($null -eq $credential) { throw 'Вход отменён.' }
    $login = $credential.GetNetworkCredential()
    $pair = '{0}:{1}' -f $login.UserName, $login.Password
    $headers.Authorization = 'Basic ' + [Convert]::ToBase64String(
        [Text.Encoding]::UTF8.GetBytes($pair)
    )
    Remove-Variable pair, login, credential
}

$http = @{
    Headers = $headers
    UseBasicParsing = $true
    MaximumRedirection = 0
    TimeoutSec = 60
}

function Read-TelemetryResult {
    param($Response, [int]$ExpectedStatus)

    $body = $Response.Content | ConvertFrom-Json
    if ([int]$Response.StatusCode -ne $ExpectedStatus -or
        $body.ok -isnot [bool] -or -not $body.ok) {
        throw "Ответ не подтверждает операцию. HTTP $($Response.StatusCode)."
    }
    $id = [Guid]::Empty
    if ($ExpectedStatus -eq 201 -and -not [Guid]::TryParseExact($body.id, 'D', [ref]$id)) {
        throw 'В ответе нет UUID записи. Проверьте историю приёмника.'
    }
    [pscustomobject]@{ Http = [int]$Response.StatusCode; Id = $body.id }
}

# 1. Проверка связи.
$response = Invoke-WebRequest @http -Method Get -Uri "$base/ping"
Read-TelemetryResult $response 200

# 2. Передача JSON из переменной.
$json = @{ source = 'powershell'; value = 42 } | ConvertTo-Json -Compress
$response = Invoke-WebRequest @http -Method Post -Uri "$base/json" `
    -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($json))
Read-TelemetryResult $response 201

# 3. Файл как бинарное тело. В URL передаётся имя файла.
$file = Get-Item -LiteralPath 'C:\Telemetry\report.log'
$name = [Uri]::EscapeDataString($file.Name)
$response = Invoke-WebRequest @http -Method Post -Uri "$base/file?name=$name" `
    -ContentType 'application/octet-stream' -InFile $file.FullName
Read-TelemetryResult $response 201
```

В планировщике передавайте токен и при необходимости учётные данные из настроек выбранного хранилища секретов. Для сохранения исходного вида уже готового JSON воспользуйтесь `-InFile` или готовым скриптом в режиме `json`. Двоичный файл передаётся одним POST. Фактический предел размера зависит от веб-сервера, платформы 1С, диска и таймаутов.

## Публикация с одним токеном

Отправитель предъявляет только `X-Token` по HTTPS. В выделенной публикации веб-сервер устанавливает соединение с 1С под служебным пользователем, а сервис телеметрии проверяет токен каждой отправки.

1. Создайте для той же базы отдельную HTTPS-публикацию, например `/Telemetry`. В базе заведите служебного пользователя и назначьте ему роль `ТЛМ_ПриемТелеметрии`. Для администрирования используйте отдельную учётную запись.
2. В `default.vrd` этой публикации укажите имя и пароль служебного пользователя в атрибуте `ib` и включите `ТЛМ_ПриемДанных`. Доступ к дескриптору на диске нужен только службе веб-сервера и администратору.
3. В правилах доступа HTTPS оставьте только `GET …/ping`, `POST …/json` и `POST …/file`. Исключите из доступа веб-клиент, OData, другие сервисы и сам `default.vrd`. Применяйте это правило к отдельной публикации.
4. Выключите **ТЛМ_Использование авторизации на сервере телеметрии** на отправителе. Проверьте, что `GET /ping` с верным токеном даёт `200`, с неверным — `401 invalid_token`, а веб-клиент и посторонние маршруты недоступны. Ответ `401` с `WWW-Authenticate: Basic` указывает, что публикация всё ещё требует входа.

[Полная настройка с примерами default.vrd и Apache](docs/INSTALLATION.md#публикация-без-basic).

## Если обмен не работает

| Симптом | Что проверить |
|---|---|
| `401 invalid_token` | Токен и флаг «Приём разрешён» в карточке отправителя |
| `401` с запросом Basic | Режим авторизации, имя и пароль публикации. Для отдельной публикации с одним токеном проверьте подключение служебного пользователя |
| `413` | Лимит JSON и настройки размера HTTP-запроса на веб-сервере. Для файла проверьте лимиты публикации |
| `503` при отправке файла | Каталог приёма и права процесса сервера 1С |
| Таймаут или разрыв связи | Проверьте, появилась ли запись в центральной базе, прежде чем повторять POST |
