# 1C-telemetry — передача JSON и файлов в 1С

Универсальный транспорт для платформы 1С:Предприятие 8.3: неопубликованные базы и внешние скрипты отправляют произвольный JSON и файлы в центральную опубликованную базу по HTTPS. Получатель сохраняет историю без анализа содержимого.

**Статус:** проектирование, разработка ещё не выполнена. Релизов пока нет.  
**Последний релиз:** пока не опубликован. · [Все релизы](https://github.com/BurimBasic/1C-telemetry/releases) · [История изменений](CHANGELOG.md)

## Архитектура

- Серверное расширение: HTTPS через существующий IIS/Apache, HTTP-сервис 1С, индивидуальные токены, справочник клиентов, два регистра истории и каталог файлов.
- Клиентское расширение: общий модуль отправки, настройки в константах. Локальная база не публикуется.
- PowerShell, Python и cURL: компактные примеры прямых запросов, без SDK.
- Заказчик самостоятельно формирует JSON в своих BSL-процедурах и настраивает штатные регламентные задания.

Никаких собственных форм, обработок, оболочек, дашбордов, планировщика, Gateway, БСП, внешней СУБД или изменений основной конфигурации. Все объекты с префиксом `ТЛМ_`. Только штатные автоматически генерируемые формы 1С.

## Быстрый старт (планируемый контракт v1)

1. Установить серверное расширение, задать константы каталога и лимита JSON (лимита размера файла нет), опубликовать только его HTTP-сервис. HTTPS настраивается администратором на веб-сервере.
2. Создать элемент справочника `ТЛМ_Клиенты`, сгенерировать уникальный токен штатным программным методом и передать отправителю.
3. В клиентской базе установить клиентское расширение и заполнить константы адреса, токена и при необходимости пути к доверенному PEM. Проверить соединение экспортным методом.
4. В собственной процедуре сформировать JSON и вызвать `ТЛМ_Клиент.ОтправитьJSON(JSON)` или `ТЛМ_Клиент.ОтправитьФайл(ПутьКФайлу)`. Расписание — штатное регламентное задание заказчика. Для файловой ИБ необходим работающий сеанс, выполняющий задания.
5. Внешний скрипт выполняет один POST с заголовком `X-Token` для любого файла или JSON. История доступна через стандартные списки регистров с отбором по клиенту.

Пример адреса: `https://server.example/central/hs/telemetry/` (также допустим IP, совпадающий с SAN сертификата).

| Метод | Маршрут | Тело |
|---|---|---|
| POST | json | UTF-8 JSON целиком |
| POST | file?name=backup.log | Бинарный файл |
| GET | ping | Нет; проверка соединения и токена |

Для самоподписанного сертификата используется доверенный публичный PEM или хранилище доверия ОС. Закрытый ключ не передаётся; отключать TLS-проверку нельзя. Авторизация только через `X-Token`, не через логин отправителя 1С.

Каждый файл передаётся одним POST без разделения, сборки и повторов. Расширение не ограничивает его размер константой. Реальный предел зависит от IIS/Apache/1С, файловой системы, памяти и таймаутов; заказчик самостоятельно делит слишком большие файлы при необходимости. Все экспортные транспортные функции возвращают одинаковую структуру результата. Подробнее: [Передача файлов и ошибки](docs/TRANSFER-AND-ERRORS.md).

## Испытания

Сервер устанавливает администратор из исходного ZIP в имеющуюся тестовую ИБ и публикует HTTP-сервис через Apache/HTTPS. Разработчик запускает реальные POST/GET с разрешённой Windows-станции, сверяет регистры и файлы. Клиентское расширение отдельно проверяется на тестовой ИБ с исполнением BSL и штатного регламентного задания; скриптовая проверка сервера не заменяет эту приёмку. [План тестирования](docs/TEST-PLAN.md).

## Поставка

Два отдельных полных ZIP исходников XML/BSL для загрузки в расширения Конфигуратором, без выдачи CFE заказчику; примеры скриптов, инструкции, SHA-256 и манифесты. Не путать исходный ZIP с CFE. Поддерживаемые версии платформы будут указаны по результатам реальной проверки; первый тестовый ориентир — 8.3.27.

**Обязанность разработчика:** при каждой поставке обновлять эту главную страницу, CHANGELOG, версию и перечень проверок; предоставлять проверенные прямые неизменяемые ссылки на последние ZIP обоих расширений и сопутствующие файлы. Не выдавать запланированные функции за реализованные, статическую проверку за CheckConfig или тестовый ZIP за установленный релиз.
