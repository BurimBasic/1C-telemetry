# Примеры 1C-telemetry

## Скрипты

Получите HTTPS URL корня сервиса и отдельный токен. Задайте `TLM_URL` и `TLM_TOKEN` в локальном окружении. Для Python или cURL при необходимости задайте `TLM_PEM` (доверенный публичный PEM). Windows PowerShell 5.1 берёт доверие из хранилища Windows. Для JSON подготовьте файл UTF-8 без BOM.

| Проверка | Windows PowerShell 5.1 | Python 3 |
|---|---|---|
| Связь | `powershell\Send-Telemetry.ps1 ping` | `python python/send_telemetry.py ping` |
| JSON | `powershell\Send-Telemetry.ps1 json report.json` | `python python/send_telemetry.py json report.json` |
| Файл | `powershell\Send-Telemetry.ps1 file отчёт.txt` | `python python/send_telemetry.py file отчёт.txt` |

В PowerShell запускайте с префиксом `.\`, если текущий каталог содержит каталог `powershell`. Для Python установите `requests` командой `python -m pip install requests` в своём окружении. Команды [cURL](curl_examples.txt) рассчитаны на Windows PowerShell и cURL 7.76+. При версии cURL ниже 7.76 можно заменить `--fail-with-body` на `--fail`. Скрипты проверяют HTTP-ответ и прикладное подтверждение. После сетевого сбоя сначала проверьте фактическую запись.

## Штатное регламентное задание

Каталог [schedule](schedule) — отдельный образец дополнения, которое загружается после `ТЛМ_Клиент` в тестовую ИБ. Скопируйте его XML/BSL в своё расширение или загрузите образец в отдельное дополнение. Задание изначально выключено. Установите стандартное расписание (для приёмки достаточно одной минуты), включите задание, запустите в сеансе с ролью отправки. Обработчик отправляет синтетический JSON с временем UTC. Для своей автоматизации замените этот JSON и правила реакции на сбой.

В клиент-серверной базе задания выполняет сервер 1С, если они разрешены для ИБ. В неопубликованной файловой ИБ по расписанию нужен работающий сеанс, выполняющий задания. После трёх запусков проверьте три различных UUID и записи с `source=schedule-test` у тестового клиента. Сверьте время и журнал запуска.
