# HTTPS API v1

Базовый URL задаётся администратором, например `https://server.example/central/hs/telemetry/`. Отправитель передаёт свой токен в заголовке `X-Token` в каждом запросе. Исходное значение назначает администратор. Кодируйте его как UTF-8 percent-encoding по RFC 3986. Символы ASCII из набора `A–Z a–z 0–9 - . _ ~` передаются буквально, остальные байты записываются как `%HH`. Строка `123` передаётся как `X-Token: 123`, строка `А %` — как `X-Token: %D0%90%20%25`. Сервер сопоставляет байты декодированного токена с исходным значением в карточке, включая регистр и пробелы. Доверие TLS настраивается по [инструкции](INSTALLATION.md).

Если HTTPS-публикация требует вход по HTTP Basic, клиент 1С с включённой настройкой добавляет `Authorization: Basic …` к первому запросу каждого маршрута. Клиент кодирует пару имя и пароль в UTF-8 и Base64. Публикация проверяет свои учётные данные до вызова HTTP-сервиса, который проверяет `X-Token`. [RFC 7617](https://www.rfc-editor.org/rfc/rfc7617.html).

| Метод | Маршрут | Тело | Успех |
|---|---|---|---|
| GET | `ping` | Пустое | 200, `{"ok":true}` |
| POST | `json` | Готовый текст UTF-8 без BOM, `application/json` | 201, `{"ok":true,"id":"<uuid>"}` |
| POST | `file?name=backup.log` | Исходные байты, `application/octet-stream` | 201, `{"ok":true,"id":"<uuid>"}` |

Для имени файла используйте UTF-8 percent-encoding. В поле `name` передавайте только исходное имя длиной до 255 символов. Пустой файл и несколько файлов с одинаковым именем допустимы. Любой принятый POST создаёт самостоятельную запись. Физический путь формирует сервер. Сервер сохраняет JSON как исходный текст с пробелами и переносами, проверяя кодировку и размер в байтах. Полезное содержимое может быть любым JSON. Дату получения хранит в UTC.

```json
{"ok":false,"error":"invalid_token","message":"Неверный или заблокированный токен"}
```

| HTTP | Машинный код | Значение |
|---|---|---|
| 400 | `bad_request`, `invalid_encoding`, `invalid_filename` | Ошибка тела, кодировки, длины или имени |
| 401 | `invalid_token` | Токен отсутствует, пуст, неверно закодирован, неизвестен, отозван или заблокирован |
| 413 | `payload_too_large` | Превышен лимит JSON или HTTP-лимит публикации |
| 415 | `unsupported_media_type` | Нужен Content-Type из таблицы маршрутов |
| 500 | `storage_error`, `internal_error` | Операция не подтверждена, источник должен проверить историю |
| 503 | `unavailable` | Операция недоступна по настройкам сервера |
| 507 | `insufficient_storage` | Причина отказа однозначно установлена; в TEST-сервере ошибки записи без надёжного признака возвращаются как 500 |

Веб-сервер может вернуть свой статус, HTML, пустой ответ или разорвать соединение. Сохраняйте фактический HTTP-статус и проверяйте `ok` и допустимый `id` вместе. При неизвестном результате сверьтесь с администратором перед повтором. Каждый повторившийся POST может создать ещё одну запись.
