## Для завершения приёмки

1. Администратор резервирует тестовую базу, импортирует сервер, выполняет CheckConfig и публикует три маршрута по HTTPS. Создаёт выделенный каталог, назначает роль техническому пользователю и регистрирует два тестовых токена. [Инструкция установки](INSTALLATION.md).
2. Передаёт тестовый URL, два токена и при необходимости публичный PEM закрытым каналом. Для сравнения байтов нужен SHA-256 физических файлов с сервера. Запуск и сверка по [плану T02–T12](TEST-PLAN.md).
3. На установленном клиенте выполняются три метода BSL и минимум три запуска штатного задания. После успешных проверок и ревью владельца комплект переносится в `main`.

Блокировка выдачи stable сохраняется до стендовой приёмки. Для файлового POST сервер использует доступные методы потока и проверяет фактическую длину. Однозначное распознавание переполнения диска в TEST не подтверждено, при ошибках записи возвращается `storage_error`. CSPRNG вызывается оператором вне 1С, штатный метод сервера регистрирует готовый 256-битный секрет.
