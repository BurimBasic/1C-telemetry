# Большие файлы и единый контракт ошибок (норматив v1)

Статус: спецификация, реализация и испытания NOT_RUN. Решение: нет константы ограничения общего размера файла; остаётся лимит JSON. Не загружать многогигабайтные файлы в RAM и не ограничивать размер Int32. Блоковая передача — часть обязательной v1, не будущая опция.

## Простой интерфейс
ТЛМ_Клиент.ОтправитьФайл(ПутьКФайлу) автоматически читает размер файла, для <=8 МиБ использует обычный POST /file?name=..., для >8 МиБ — блоковый протокол. 8 МиБ = 8388608 байт, внутренний технический размер блока (последний меньше), не лимит полного файла, без отдельной константы. Файл должен оставаться неизменным на протяжении передачи. Использовать файловые потоки/ограниченное чтение, отдельно проверить BSL API по версии платформы. Обычный POST из скрипта сохраняется без изменений; сервер не вводит дополнительный максимум полного файла, но инфраструктура может отклонить большой запрос. Для больших файлов дать готовый PowerShell/Python/cURL пример чтения блоков с диска, не требовать вручную писать протокол. Не использовать base64.

## Блоковый HTTPS API
Все запросы: X-Token, клиент определяется только по токену. upload_id — UUID отправителя, уникален в рамках клиента, служит для идемпотентности одной передачи. Размеры/offset в байтах (64-битная семантика, целые, не отрицательные). Временный файл находится на диске сервера в защищённом каталоге; отдельный служебный регистр ТЛМ_ЗагрузкиФайлов, без собственного UI. Сериализовать запись одной загрузки; разные загрузки независимы.

| Метод и адрес | Данные | Успех |
|---|---|---|
| POST file/init | JSON upload_id, name, size, sha256 исходного файла | 200: ok, upload_id, offset |
| POST file/part?upload_id=...&offset=... | raw bytes блока, application/octet-stream | 200: ok, upload_id, offset (следующее смещение) |
| GET file/status?upload_id=... | нет | 200: ok, upload_id, offset, state, id после завершения |
| POST file/complete?upload_id=... | без тела | 201: ok, id; повтор 200 с прежним id |

init повторяем только с теми же параметрами; несоответствие — 409. Принимаются последовательные блоки по ожидаемому смещению; блок ограничен 8 МиБ и оставшимся размером. Повтор уже подтверждённого блока только при совпадении данных с записанным диапазоном; вернуть актуальное смещение, не дописывать второй раз. Неверный offset/перекрытие/расхождение — 409. Подтверждения после фактической записи и фиксации состояния; при неизвестном исходе использовать status, не создавать новый upload_id автоматически. Повтор сети только ограниченно и документированно для безопасных идемпотентных операций. Таймаут каждого HTTP-запроса отдельно, исходная константа 60 секунд. Проверить восстановление состояния при расхождении файла и зарегистрированного offset после аварии (не считать неподтверждённый блок принятым). При complete проверить фактический размер и SHA-256 потоково/с диска; только затем финализировать файл и зарегистрировать одну запись в ТЛМ_ПолученныеФайлы. Повтор complete возвращает тот же id. Не создавать итоговую запись при незавершённой загрузке. Возобновление после нового вызова функции/рестарта клиента не обещается в v1; статус и повтор в рамках того же upload_id поддерживаются. Незавершённые файлы удаляются только администратором безопасной документированной процедурой; история завершённых не удаляется. Никаких дополнительных констант, произвольного фонового планировщика, скрытого буфера всего файла.

## BSL: результат каждой экспортной транспортной функции
ОтправитьJSON, ОтправитьФайл, ПроверитьПодключение — функции, возвращают Структура с одинаковыми полями:
| Поле | Тип | Смысл |
|---|---|---|
| Успех | Булево | Истина только при подтверждённом ответе сервера и завершённой операции |
| КодОшибки | Строка | Пустая при успехе, стабильный машинный код при ошибке |
| ОписаниеОшибки | Строка | Понятное русское описание, без токена/секретов/чужих данных |
| КодHTTP | Число | Реальный HTTP-код; 0 при отсутствии ответа |
| Идентификатор | Строка | ID принятой записи при успехе отправки, иначе пусто |
| Состояние | Строка | ПОДТВЕРЖДЕНО / ОТКЛОНЕНО / НЕИЗВЕСТНО (при отсутствии подтверждения и возможной записи) |
| ИдентификаторЗагрузки | Строка | upload_id при блоковой передаче, иначе пусто |

Штатные ошибки ввода, настройки, чтения, сети, TLS, HTTP, ответа и записи обрабатывать внутри модуля и возвращать результат. Не использовать Сообщить/Предупреждение, не требовать Попытка/Исключение для обычной ошибки. Журнал регистрации только безопасные сведения; заказчик сам решает, писать ли лог и повторять ли отправку. Непредвиденные ошибки обрабатывать по возможности с безопасной диагностикой; завершение процесса/фатальная ошибка платформы вне гарантии. Для административных методов токенов также единый статус ошибки; генерация возвращает секрет только при успехе (поле Токен), не логирует его. Не использовать имя поля или текст ошибки как критерий успеха, проверять Успех.

Стабильные коды: invalid_settings, file_not_found, file_read_error, connection_error, tls_error, timeout, invalid_token, bad_request, invalid_encoding, invalid_filename, payload_too_large, unsupported_media_type, upload_conflict, offset_mismatch, checksum_mismatch, insufficient_storage, storage_error, unavailable, invalid_response, internal_error. Не определять TLS/timeout догадкой: при невозможности точной классификации connection_error. Для неизвестной доставки Состояние=НЕИЗВЕСТНО, Успех=Ложь: запрос мог быть сохранён. Не повторять обычный POST автоматически. Локальная ошибка до передачи — ОТКЛОНЕНО. Неожиданный HTML, редирект и 2xx без ожидаемого ok/id не означают успех. При частичной загрузке успех всей операции только после complete.

## HTTP: ответ внешним скриптам
Успешный POST 201 {"ok":true,"id":"..."}; ping 200 {"ok":true}; блоковые ответы указаны выше. Ошибки JSON {"ok":false,"error":"invalid_token","message":"Неверный или заблокированный токен"} с HTTP 401. Дополнительно 400 неверный запрос, 404 неизвестная/чужая загрузка, 409 конфликт размера/смещения/хеша, 413 слишком большой запрос (инфраструктура, JSON или блок; не лимит общего файла), 415 неподдерживаемый тип, 500 ошибка записи, 503 временно недоступно, 507 недостаточно места. Чужая загрузка не раскрывается. Веб-сервер может вернуть свой HTML или закрыть соединение; явно диагностировать HTTP-код/неизвестный исход. PowerShell обрабатывает catch, Python raise_for_status, curl --fail/--fail-with-body и код завершения; примеры должны проверять также успешный JSON.

## Приёмка
Реальные файлы 2 и 3 ГиБ, проверка SHA-256 с обеих сторон и пик RAM; дополнительный >4 ГиБ при доступности среды. Проверить offset после 2 ГиБ, повтор блока/complete, обрыв сети, параллельность, другой токен, заполнение диска, несовпадение хеша, неверный HTTP-запрос, обычный файл/JSON одним запросом, стабильный результат BSL во всех штатных сценариях. Указать платформу/веб-сервер/ОС, настройки и фактические пределы. Отдельно измерить время и RAM. Не обещать безграничность: ограничивают диски/ФС/ресурсы/настройки инфраструктуры.
