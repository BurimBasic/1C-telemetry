# Прямая передача файлов и единый контракт ошибок (норматив v1)

Комплект TEST и результаты испытаний описаны в [отчёте WAVE 001](ACCEPTANCE.md). Решение владельца: один файл — один POST. Не ограничивать размер файла константой; остаётся лимит JSON. Заказчик самостоятельно делит большие файлы, если это необходимо. Не создавать механизмы деления, сборки, возобновления, регистрации незавершённых передач или повторов.

## Простой интерфейс
ТЛМ_Клиент.ОтправитьФайл(ПутьКФайлу) отправляет один исходный файл через POST /file?name=... с X-Token и application/octet-stream. Имя UTF-8 percent-encoded; содержимое неизменно, без base64. Клиент указывает файл как тело запроса. Сервер копирует поток HTTP-тела во временный файл. Фактическую буферизацию веб-сервера и 1С предстоит измерить. Сервер сохраняет файл на диск под уникальным именем, фиксирует запись с клиентом, датой, размером и путём после полного приёма. Один запрос — одна запись. При отказе не регистрировать неполный файл как полученный; безопасно удалить свой временный файл. Повторный вызов — новая запись. Не гарантировать произвольный размер: предел одного запроса зависит от платформы, веб-сервера, памяти, диска, ФС и таймаута. Клиентский таймаут настраивается константой. Прямой POST скриптов использует тот же контракт без дополнительных шагов.

## BSL: результат каждой экспортной транспортной функции
ОтправитьJSON, ОтправитьФайл, ПроверитьПодключение — функции, возвращают Структура с одинаковыми полями:
| Поле | Тип | Смысл |
|---|---|---|
| Успех | Булево | Истина только при подтверждённом ответе сервера и завершённой операции |
| КодОшибки | Строка | Пустая при успехе, стабильный машинный код при ошибке |
| ОписаниеОшибки | Строка | Понятное русское описание, без токена/секретов/чужих данных |
| КодHTTP | Число | Реальный HTTP-код; 0 при отсутствии ответа |
| Идентификатор | Строка | ID принятой записи при успехе отправки, иначе пусто |
| Состояние | Строка | ПОДТВЕРЖДЕНО / ОТКЛОНЕНО / НЕИЗВЕСТНО (при отсутствии подтверждения и возможной записи) |

Штатные ошибки ввода, настройки, чтения, сети, TLS, HTTP, ответа и записи обрабатывать внутри модуля и возвращать результат. Не использовать Сообщить/Предупреждение, не требовать Попытка/Исключение для обычной ошибки. Журнал регистрации только безопасные сведения; заказчик сам решает, писать ли лог и повторять ли отправку. Непредвиденные ошибки обрабатывать по возможности с безопасной диагностикой; завершение процесса/фатальная ошибка платформы вне гарантии. Для административных методов токенов также единый статус ошибки; регистрация готового секрета возвращает его только при успехе в поле Токен. Не использовать имя поля или текст ошибки как критерий успеха, проверять Успех.

Для публикации с HTTP Basic задайте настройки входа в клиенте. Если имя пользователя не задано или учётные данные содержат запрещённые символы, клиент возвращает `invalid_settings` до вызова. При HTTP 401 от публикации без JSON сервиса клиент возвращает `invalid_response` с HTTP-кодом 401. JSON-ответ HTTP-сервиса об отклонении токена даёт `invalid_token`.

Стабильные коды: invalid_settings, file_not_found, file_read_error, connection_error, tls_error, timeout, invalid_token, bad_request, invalid_encoding, invalid_filename, payload_too_large, unsupported_media_type, insufficient_storage, storage_error, unavailable, invalid_response, internal_error. Не определять TLS/timeout догадкой: при невозможности точной классификации connection_error. Для неизвестной доставки Состояние=НЕИЗВЕСТНО, Успех=Ложь: запрос мог быть сохранён. Не повторять обычный POST автоматически. Локальная ошибка до передачи — ОТКЛОНЕНО. Неожиданный HTML, редирект и 2xx без ожидаемого ok/id не означают успех.

## HTTP: ответ внешним скриптам
Успешный POST 201 {"ok":true,"id":"..."}; ping 200 {"ok":true}. Ошибки JSON {"ok":false,"error":"invalid_token","message":"Неверный или заблокированный токен"} с HTTP 401. Дополнительно 400 неверный запрос, 413 слишком большой запрос (инфраструктура или лимит JSON; не установленный расширением лимит файла), 415 неподдерживаемый тип, 500 ошибка записи, 503 временно недоступно. Код 507 предусмотрен для подтверждённого переполнения, при неопределённой причине запись возвращает 500. Веб-сервер может вернуть свой HTML или закрыть соединение; явно диагностировать HTTP-код/неизвестный исход. Примеры PowerShell, Python и cURL проверяют HTTP-статус и прикладные поля JSON.

## Приёмка
Проверить обычный файл и JSON одним запросом, пустой файл, кириллицу в имени, повторную отправку, параллельность, заполнение диска, обрыв сети, ошибки сертификата и токена. При доступной среде испытать прямую отправку 2 и 3 ГиБ, сравнить SHA-256 обеих копий, измерить время и RAM, зафиксировать фактический предел. Большие файлы не являются поводом внедрять отдельный протокол. Непроведённый тест помечается NOT_RUN; документировать ограничения платформы, веб-сервера, ФС, памяти и таймаутов.
