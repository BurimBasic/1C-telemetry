# Установка и эксплуатация (проект инструкции)

## Центральная база
Сделать резервную копию и установить серверное расширение в тестовую копию. Исходный ZIP распаковать в пустой каталог и загрузить в расширение, а не в основную конфигурацию. Настроить константы ТЛМ_Сервер_*; создать защищённый каталог на машине выполнения сервера 1С/веб-расширения, не внутри web root. Проверить доступ процесса и место на диске. Создать клиентов штатным справочником, сгенерировать токены программно из администраторского BSL и передать по доверенному каналу.
Публиковать только ТЛМ_ПриемДанных; существующую публикацию и другие сервисы не ломать. Для token-only требуется возможность входа HTTP-сервиса под минимально уполномоченным техническим пользователем 1С, настроенным на сервере (вариант отдельной ограниченной публикации/default.vrd); реальные параметры подтвердить на платформе и IIS/Apache. Не раскрывать пароль технического пользователя отправителям. Не публиковать веб-клиент/OData от имени этого пользователя. При белом IP ограничить доступ к сервису доверенной сетью, если возможно.
Журнал истории — стандартные списки регистров, отбор по клиенту и дате; хранение без автоочистки. Резервное копирование включает ИБ и каталог файлов согласованно.

## Большие файлы

Нет константы ограничения общего размера файла. Учесть свободное место, файловую систему, права процесса, лимит тела и таймаут веб-сервера/прокси. IIS по умолчанию 30 000 000 байт; Apache 2.4.54+ по умолчанию 1 ГиБ. Настроить инфраструктуру под необходимый размер запроса; фактическая допустимая величина зависит также от платформы и памяти. Таймаут клиента применяется к прямому запросу, для больших файлов администратор задаёт подходящее значение. Если файл не проходит целиком, заказчик самостоятельно делит его и отправляет каждую часть отдельным вызовом; расширение не делит и не собирает файлы. См. [контракт](TRANSFER-AND-ERRORS.md).

## HTTPS
Использовать уже существующий HTTPS-сертификат. Сертификат не передаётся в теле запросов; сервер предъявляет его при TLS handshake. Клиент проверяет цепочку, срок, SAN для точного IP/DNS. Для доверенного публичного УЦ ничего дополнительно не нужно. Для самоподписанного серверного сертификата администратор экспортирует только публичную часть PEM (или сертификат собственного УЦ), передаёт доверенным каналом, сверяет отпечаток, указывает путь в клиентской константе либо импортирует в системное доверие. Закрытый ключ/PFX не копировать на клиенты. PowerShell использует Windows trust; Python requests/cURL могут указать PEM явно. Проверить доверие для именно того пользователя/процесса, который выполняет запрос. При замене самоподписанного сертификата обновить доверие. При несовпадении SAN необходимо перевыпустить сертификат или использовать правильное имя; не отключать проверку. Генерация и публикация сертификата не входят в расширения.

## Клиентская база
Установить клиентское расширение; заполнить ТЛМ_Клиент_АдресСервера, ТЛМ_Клиент_Токен, при необходимости ТЛМ_Клиент_ПутьКСертификату, ТЛМ_Клиент_Таймаут. Константы стандартные, без собственной формы. Для пути к файлу/PEM учитывается машина исполнения BSL, не компьютер тонкого клиента. Вызвать ПроверитьПодключение() в администраторском BSL. Настроить свои процедуры и штатные задания в собственном расширении; пример входит в план поставки. Для файла ИБ проверить фактическое исполнение при работающем разрешённом сеансе; при закрытой базе нужен организованный заказчиком запуск. Клиентские ИБ не публикуются. Расписания не являются параметрами транспортного расширения.

## Обновление и откат
Сверить SHA-256 ZIP и манифест; исходники от exact SHA. Сделать backup ИБ и каталогов. Протестировать обе стороны и совместимость до рабочей установки. Не удалять регистры, истории, справочники и файлы при обновлении. Откат версии с изменением структуры данных требует штатного восстановления резервной копии с учётом новых записей. Не обещать безусловное обратное применение старого расширения. При проблемах блокировать токен/отключить публикацию сервиса; не менять чужие публикации.

Статус: инструкция будет уточнена по фактической сборке/приёмке. Версии платформы и конкретные права публикации пока не подтверждены.
