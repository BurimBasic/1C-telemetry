# Установка и эксплуатация

Скачайте сервер 1.0.9-dev, клиент 1.0.7-dev и примеры 1.0.4-dev с [главной страницы](../README.md). Перед обновлением сохраните резервную копию каждой базы. Комплект проверен с 1С:Предприятием 8.3.27.2342 и HTTPS-публикацией Apache.

## 1. Установка сервера

1. Сверьте ZIP с опубликованным SHA-256. Например, в PowerShell: `Get-FileHash -Algorithm SHA256 .\имя.zip`.
2. Распакуйте серверный ZIP в пустой каталог. Файл `Configuration.xml` находится в его корне. В Конфигураторе выполните **Конфигурация → Расширения конфигурации**, создайте дополнение `ТЛМ_Сервер`, откройте его и загрузите конфигурацию из файлов. Выполните штатную проверку конфигурации (CheckConfig), сохраните её и обновите конфигурацию базы данных для расширения. Зафиксируйте подробный лог.
   При обновлении сервера загрузите исходники актуального ZIP в существующее дополнение `ТЛМ_Сервер`. После применения откройте новый сеанс 1С.
   Комплект поставки использует заимствованный основной язык Русский и режим интерфейса «Такси и версия 8.2». Если целевая конфигурация использует другой профиль, согласуйте контролируемые свойства в Конфигураторе.
3. На Windows при пустой настройке файлы хранятся в `C:\temp`. При первой авторизованной загрузке папка будет создана, если её ещё нет. Проверьте права учётной записи процесса исполнения 1С на создание и запись. Для своего каталога создайте папку вне корня сайта и задайте её абсолютный путь, например `D:\Telemetry` или `/var/lib/telemetry`. На Linux укажите путь явно. Ограничьте доступ к каталогу учётной записью процесса 1С и администратором. Задайте штатные разрешения файловых операций в профиле безопасности, если он используется. Выбирайте каталог и родительский путь без символических ссылок и junction. В многосерверном кластере направьте обработку в один и тот же защищённый каталог или выделите узел исполнения.
4. Назначьте `ТЛМ_АдминистраторСервера` оператору настроек. Отдельному техническому пользователю публикации назначьте `ТЛМ_ПриемТелеметрии`. У него есть программное чтение справочника клиентов и чтение/обновление двух регистров. Это права платформы, необходимые для записи. Ограничение до добавления новых записей обеспечивается кодом обработчиков и границей выделенной публикации. Уберите прикладные роли, доступ к UI, администрирование, выполнение произвольного кода. Сверьте фактически действующие права и права по умолчанию базовой конфигурации.
5. В 1С откройте **Функции для технического специалиста → Константы → ТЛМ_Каталог файлов телеметрии** (`ТЛМ_Сервер_КаталогФайлов`). В Windows оставьте поле пустым для работы с `C:\temp` или укажите свой путь. Для настройки лимита откройте **ТЛМ_Лимит JSON (МиБ)** (`ТЛМ_Сервер_МаксимальныйРазмерJSONМБ`). Для административного BSL используйте [пример настройки](../examples/bsl/НастройкаСервера.bsl). Значение 0 применяет лимит JSON 10 МиБ, положительное число задаёт лимит в МиБ, отрицательное отключает приём JSON до исправления. Ping и приём JSON работают независимо от настройки каталога.

### Регистрация токена

Создайте один элемент справочника `ТЛМ_Клиенты` на базу или скрипт. В штатной карточке введите наименование, заполните поле `Токен` собственной непустой строкой и включите «Приём разрешён». В карточке токен виден при вводе и редактировании. Например, на стенде можно указать `123`. В клиентской базе внесите ту же строку в `ТЛМ_Клиент_Токен`. В скрипте задайте исходную строку в `TLM_TOKEN`. Регистр и пробелы значимы. Дубликат отклоняется при сохранении второго клиента.

При обновлении с 1.0.0–1.0.3-dev заполните новое поле `Токен` в существующих карточках. Можно взять исходное значение из настроек отправителя или задать новое на обеих сторонах. Ссылки клиентов и записи истории сохраняются при обновлении расширения в той же базе. Смените токен обычным редактированием поля. Для блокировки снимите флаг «Приём разрешён». Уже принятый запрос может закончить запись.

Допустимая длина заголовка зависит от цепочки прокси, веб-сервера и 1С. Учитывайте длину после кодирования по [контракту API](API.md). Ограничьте доступ к карточкам и константам. Значения токенов исключите из журналов веб-сервера, 1С и клиентских скриптов.

### Публикация без Basic

Отправитель передаёт только `X-Token` по HTTPS. Веб-сервер подключается к базе под служебным пользователем, а `ТЛМ_ПриемДанных` проверяет токен и связывает запрос с клиентом из справочника.

1. Создайте отдельную публикацию той же инфобазы, например `/Telemetry`. Подготовьте служебного пользователя 1С с ролью `ТЛМ_ПриемТелеметрии`.
2. В `default.vrd` отдельной публикации сохраните параметры подключения к своей базе и добавьте `Usr` и `Pwd` служебного пользователя в атрибут `ib`. Храните дескриптор с ограниченными правами ОС и закрывайте его от доступа по HTTP. В примере все значения подключения условные. [Пример служебного подключения в документации 1С](https://its.1c.ru/db/content/metod81/src/appsolutionselffinanced/small%2520business/crm/telephony/i8106966.htm).
3. В дескрипторе включите сервис `ТЛМ_ПриемДанных` с корнем `telemetry`. На веб-сервере разрешите только три маршрута и указанные методы. Остальные адреса этой публикации, включая веб-клиент, OData, другие сервисы и сам дескриптор, закройте. [Руководство по публикации в 1С 8.3.27](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/).

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       base="/Telemetry"
       ib="Srvr=&quot;server-1c.example&quot;;Ref=&quot;TestBase&quot;;Usr=&quot;TelemetryReceiver&quot;;Pwd=&quot;REPLACE_IN_PRIVATE_DESCRIPTOR&quot;;">
    <standardOdata enable="false"/>
    <ws enable="false" pointEnableCommon="false" publishExtensionsByDefault="false"/>
    <httpServices publishByDefault="false" publishExtensionsByDefault="false">
        <service name="ТЛМ_ПриемДанных" rootUrl="telemetry" enable="true"/>
    </httpServices>
</point>
```

После штатной публикации на Apache добавьте правило в её HTTPS-виртуальный хост. Если TLS завершает обратный прокси, ограничьте доступ к внутреннему Apache этим прокси. Проверьте конфигурацию командой `apachectl -t` перед перезагрузкой конфигурации. [Документация Apache по `Require expr`](https://httpd.apache.org/docs/2.4/mod/mod_authz_core.html#require).

```apache
<LocationMatch "^/Telemetry(?:/|$)">
    <RequireAny>
        Require expr "%{REQUEST_METHOD} == 'GET' && %{REQUEST_URI} == '/Telemetry/hs/telemetry/ping'"
        Require expr "%{REQUEST_METHOD} == 'POST' && %{REQUEST_URI} in { '/Telemetry/hs/telemetry/json', '/Telemetry/hs/telemetry/file' }"
    </RequireAny>
</LocationMatch>
```

С машины отправителя выполните два запроса. Подставьте своё имя сервера и действующий токен. В Windows PowerShell используйте `curl.exe`. Для токена со спецсимволами используйте [кодирование API](API.md).

```sh
curl -i -H "X-Token: YOUR_TOKEN" "https://server.example/Telemetry/hs/telemetry/ping"
curl -i "https://server.example/Telemetry/hs/telemetry/ping"
```

Первый запрос должен вернуть `200` и `{"ok":true}`, второй — `401` с JSON-кодом `invalid_token`. Ответ `401` с пустым телом и `WWW-Authenticate: Basic` указывает на запрос входа до обработчика телеметрии. С той же машины проверьте, что веб-клиент и соседние сервисы закрыты. При данных для отправки проверьте `POST /json` и `POST /file?name=...` и найдите записи по возвращённым идентификаторам.

### Просмотр данных в 1С

Откройте принимающую базу в режиме «1С:Предприятие» под своей администраторской учётной записью. В меню **Сервис и настройки → Функции для технического специалиста** откройте нужный объект. В строке поиска введите `ТЛМ_`. Если пункта меню нет, включите **Режим технического специалиста** в **Настройки → Параметры**. [Руководство 1С по включению режима](https://v8.1c.ru/metod/article/sistema-vzaimodeystviya-novye-vozmozhnosti-dlya-sovmestnoy-raboty-na-udalenke.htm).

| Что посмотреть | Где открыть | Что искать |
|---|---|---|
| Клиенты и токены | Справочники → ТЛМ_Клиенты телеметрии (`ТЛМ_Клиенты`) | Откройте карточку клиента и посмотрите поле «Токен» и флаг «Приём разрешён». Начиная с сервера 1.0.6-dev токен виден в карточке как текст. |
| JSON | Регистры сведений → ТЛМ_Полученные JSON (`ТЛМ_ПолученныеJSON`) | Найдите запись по клиенту, дате или ID из ответа HTTP. Откройте запись и посмотрите исходный текст в поле `JSON`. |
| Файлы | Регистры сведений → ТЛМ_Полученные файлы (`ТЛМ_ПолученныеФайлы`) | Выберите строку и нажмите «ТЛМ_Скачать файл». В списке видны исходное имя, размер и путь относительно каталога приёма. |

Новые файлы сохраняются на сервере по пути `<каталог приёма>/<UUID>/<исходное имя>`. Например, на Windows при пустой настройке это `C:\temp\<UUID>\telemetry-test.txt`. Команда «ТЛМ_Скачать файл» также читает ранее принятые `<UUID>.bin` по их сохранённому пути и предлагает исходное имя, если оно допустимо для файла. Размещение таких файлов на диске сохраняется.

Добавьте три открытых списка в «Избранное» через звёздочку у заголовка. Для регулярного просмотра открывайте их из «Избранного» и отбирайте записи по клиенту. [Руководство пользователя 1С по избранному](https://v8.1c.ru/upload/static/instrukciya-po-ehkspluatacii-v8.pdf).

## 2. Установка клиента

В клиентской ИБ аналогично загрузите клиентский ZIP в отдельное дополнение `ТЛМ_Клиент`. Публикация этой ИБ не нужна. Назначьте `ТЛМ_АдминистраторКлиента` тому, кто задаёт настройки, и `ТЛМ_ОтправкаТелеметрии` — исполнителю серверного BSL или задания. Для настройки откройте «Функции для технического специалиста» → «Константы» и введите `ТЛМ_` в поиск. Роль исполнителя даёт чтение настроек, включая токен и учётные данные публикации. Назначайте её доверенной учётной записи.

| Название в 1С | Техническое имя | Значение |
|---|---|---|
| ТЛМ_HTTPS-адрес сервера | `ТЛМ_Клиент_АдресСервера` | Например `https://server.example/central/hs/telemetry/`. Допустим нестандартный порт и вложенный путь. |
| ТЛМ_Токен отправителя | `ТЛМ_Клиент_Токен` | Исходный токен из карточки клиента. |
| ТЛМ_Путь к сертификату | `ТЛМ_Клиент_ПутьКСертификату` | Путь к публичному PEM или пустая строка для доверия ОС. |
| ТЛМ_Таймаут (сек.) | `ТЛМ_Клиент_Таймаут` | Целые секунды. 0 применяет 60, отрицательные значения отклоняются. |
| ТЛМ_Имя пользователя сервера телеметрии | `ТЛМ_Клиент_ИмяПользователяСервераТелеметрии` | Имя пользователя публикации принимающей базы. Учитывается при включённой авторизации. |
| ТЛМ_Пароль пользователя сервера телеметрии | `ТЛМ_Клиент_ПарольПользователяСервераТелеметрии` | Пароль этого пользователя. Поле маскируется. Пустое значение допустимо, если у тестового пользователя публикации пустой пароль. |
| ТЛМ_Использование авторизации на сервере телеметрии | `ТЛМ_Клиент_ИспользованиеАвторизацииНаСервереТелеметрии` | «Да» для публикации с HTTP Basic. По умолчанию «Нет» и отправляется только X-Token. |

Файл и PEM должны быть доступны на машине, которая исполняет серверный BSL. В серверном режиме это рабочий процесс 1С, в файловом — исполняющий сеанс. Проверьте исходящий HTTPS и чтение только нужных путей. Пример настройки и вызовов в [НастройкаКлиента.bsl](../examples/bsl/НастройкаКлиента.bsl). В каждом расширении есть русская HTML-страница штатной справки в `Ext/Help` подсистемы справки. Проверка отображения включена в установочную приёмку.

### Проверка клиента из отдельной тестовой базы

Под ролью `ТЛМ_АдминистраторКлиента` откройте раздел **ТЛМ_Клиент телеметрии** и команду **ТЛМ_Проверка телеметрии**. Форму также можно найти через «Функции для технического специалиста» → «Обработки» или через «Перейти по ссылке…» по адресу `e1cib/app/Обработка.ТЛМ_ПроверкаТелеметрии`.

| Поле или кнопка | Метод | Результат |
|---|---|---|
| Версия клиента | `ТЛМ_Клиент.Версия()` | Показывает установленную версию общего модуля при открытии формы |
| Проверить подключение | `ТЛМ_Клиент.ПроверитьПодключение()` | При правильных параметрах в результате отображается HTTP 200 |
| Отправить JSON | `ТЛМ_Клиент.ОтправитьJSON(ТекстJSON)` | Вставьте тело запроса в поле «Тело JSON». Успех возвращает HTTP 201 и UUID записи |
| Выбрать файл → Отправить файл | `ТЛМ_Клиент.ОтправитьФайл(ПутьКФайлу)` | Выберите локальный файл, затем отправьте его отдельной кнопкой. Успех возвращает HTTP 201 и UUID записи |

Скопируйте UUID после каждой отправки из поля «Результат последней операции». На принимающей стороне найдите их в регистрах «ТЛМ_Полученные JSON» и «ТЛМ_Полученные файлы». Сверьте содержимое, имя файла и отправителя. При неизвестном результате проверьте регистр до повтора.

Форма предназначена для проверки с небольшими файлами. При выборе платформа сначала загружает файл в текущую базу, и лишь при отправке тот уходит на принимающий сервер. Для штатной отправки больших файлов вызывайте `ТЛМ_Клиент.ОтправитьФайл()` с путём к файлу, доступному серверному коду.

#### Запуск из серверного BSL

1. На принимающей стороне заведите отдельного клиента с разрешённым приёмом и собственным токеном. На отправителе задайте HTTPS-адрес корня сервиса, токен и параметры входа для этой публикации.
2. Выполните следующий фрагмент в серверном контексте 1С из клиентской базы, например из имеющейся административной консоли BSL. `PING` должен вывести 200. `JSON` и `FILE` должны вывести 201 и два разных идентификатора.

```bsl
Пинг = ТЛМ_Клиент.ПроверитьПодключение();
Сообщить("PING " + Строка(Пинг.КодHTTP) + " " + Пинг.КодОшибки);
Если Пинг.Успех Тогда
	Метка = Строка(Новый УникальныйИдентификатор);
	Текст = "{""source"":""client-smoke"",""id"":""" + Метка + """}";
	ИтогJSON = ТЛМ_Клиент.ОтправитьJSON(Текст);
	Сообщить("JSON " + Строка(ИтогJSON.КодHTTP) + " " + ИтогJSON.КодОшибки
		+ " " + ИтогJSON.Идентификатор);

	Путь = ПолучитьИмяВременногоФайла("txt");
	Байты = ПолучитьДвоичныеДанныеИзСтроки(Текст, КодировкаТекста.UTF8, Ложь);
	Байты.Записать(Путь);
	Файл = Новый Файл(Путь);
	ИтогФайла = ТЛМ_Клиент.ОтправитьФайл(Путь);
	Сообщить("FILE " + Строка(ИтогФайла.КодHTTP) + " " + ИтогФайла.КодОшибки
		+ " " + ИтогФайла.Идентификатор + " " + Файл.Имя);
	УдалитьФайлы(Путь);
КонецЕсли;
```

3. В принимающей базе найдите оба идентификатора в «ТЛМ_Полученные JSON» и «ТЛМ_Полученные файлы». Сверьте отправителя и текст с меткой. Скачайте файл из регистра и проверьте имя и содержимое.
4. На выделенном тестовом отправителе повторите только `ПроверитьПодключение()`. Для публикации с HTTP Basic выключите переключатель и ожидайте 401 от публикации. Восстановите переключатель, задайте неправильный тестовый токен и ожидайте 401 с кодом `invalid_token`. Верните рабочий токен и подтвердите 200. Для публикации, где вход обеспечен на стороне веб-сервера, отдельно подтвердите 200 при выключенном переключателе и верном токене.

## Состав расширений

| Объекты | Принимающая база · `ТЛМ_Сервер` | База-отправитель · `ТЛМ_Клиент` |
|---|---|---|
| Обмен | HTTP-сервис `ТЛМ_ПриемДанных`, общий модуль `ТЛМ_Сервер` | Общий модуль `ТЛМ_Клиент`, обработка `ТЛМ_ПроверкаТелеметрии` |
| Данные | Справочник `ТЛМ_Клиенты`, регистры сведений `ТЛМ_ПолученныеJSON` и `ТЛМ_ПолученныеФайлы` | Настройки отправителя в константах |
| Константы | `ТЛМ_Сервер_КаталогФайлов`, `ТЛМ_Сервер_МаксимальныйРазмерJSONМБ` | Адрес, токен, PEM, таймаут и три настройки HTTP Basic из таблицы установки клиента |
| Роли | `ТЛМ_ПриемТелеметрии`, `ТЛМ_АдминистраторСервера` | `ТЛМ_ОтправкаТелеметрии`, `ТЛМ_АдминистраторКлиента` |
| Справка и язык | `ТЛМ_СправкаСервера`, Русский | `ТЛМ_СправкаКлиента`, Русский |

## Сертификаты, диск и большие файлы

Для частного УЦ или самоподписанного сертификата получите публичный PEM закрытым доверенным способом и сверьте отпечаток. Администратор добавляет его в доверие ОС для нужной учётной записи либо указывает PEM в клиентской константе. В Windows PowerShell 5.1 используется доверие Windows, Python и cURL могут принять публичный PEM. SAN должен соответствовать URL: IP указывают как IP в SAN, имя — как DNS. После смены самоподписанного сертификата обновите доверие.

Один файл идёт одним POST. Контролируйте место на томе каталога и томе временных файлов веб-сервера, а также память и таймауты. У Apache проверьте [LimitRequestBody и таймауты](https://httpd.apache.org/docs/2.4/mod/core.html#limitrequestbody) для конкретной публикации. У IIS проверьте [requestFiltering / maxAllowedContentLength](https://learn.microsoft.com/iis/configuration/system.webserver/security/requestfiltering/requestlimits/). BSL использует файловое тело на отправке и поток запроса на приёме. Буферизацию транспорта Apache/1С и предел 2–3 ГиБ устанавливают измерением. При неопределённой причине ошибки записи сервер возвращает `storage_error`; ёмкость диска проверяет администратор. Подробности в [контракте ошибок](TRANSFER-AND-ERRORS.md).

## Резервное копирование и откат

Резервируйте ИБ и файловый каталог вместе в согласованной точке. Перед обновлением остановите приём в выделенной публикации, дождитесь окончания запросов, сделайте резервные копии и снимок дескриптора. Загрузите новый ZIP в существующее расширение, проверьте CheckConfig, восстановите публикацию и выполните smoke с двумя токенами. Для отката используйте согласованные копии ИБ и диска. Простое удаление серверного расширения может удалить данные его регистров.

Операции с диском и БД фиксируются отдельно. При аварии между переименованием и фиксацией возможен файл `<UUID>/<исходное имя>` без строки регистра. После прерванной загрузки возможен `<UUID>.tmp` или пустой подкаталог `<UUID>`. При остановленном приёме сверяйте UUID, дату и размер с регистром. Удаление проверенных сирот и тестовых данных выполняет администратор. Старые файлы, соответствующие строкам регистра, сохраняются.
