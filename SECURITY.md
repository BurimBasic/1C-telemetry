# Безопасность 1C-telemetry

Публичный репозиторий. Не коммитить токены, пароли, ключи, частные адреса, реальные JSON клиентов, логи, дампы или пути инфраструктуры. Только синтетические тесты. При утечке немедленно отозвать токен, сообщить владельцу приватно, не помещать секреты в issue.

HTTPS обязательный, проверка цепочки, срока и имени/IP, без insecure-опций. Токен — индивидуальный high-entropy bearer, передача X-Token, серверное хранение хеша, отзыв/ротация заказчиком; не принимать identity из тела. Копия действующего токена позволяет отправлять от имени клиента; не считать привязкой к ПК. Fail-closed при проблемах с TLS, токеном, настройками, правами, файлами/БД. Не логировать секреты и содержимое сообщений. Публичный API только приём и ping, нет чтения, удаления, исполнения и управления токеном. Технический пользователь минимальных прав, отдельная публикация, ограничения сети/веб-сервера по возможности.

Хранить файл за пределами web root, путь только серверный, исключить traversal и перезапись, не извлекать архивы, не выполнять содержимое, контролировать лимит JSON, фактически полученные байты и свободное место (без установленного расширением лимита общего размера файла); документировать ограничения памяти. Не доверять клиентскому имени/типу/размеру. JSON непрозрачные данные, не код. Регистр и файл должны согласованно отражать успех, аварийные окна описать. Каждый POST авторизовать отдельно. Запись в реестре только после успешного сохранения полного файла; при ошибке не выдавать success и удалять только свой временный файл, согласно безопасной процедуре. Не выполнять автоматические повторы. Историю не чистить автоматически; резервировать ИБ и диск.

Негативные тесты: неизвестный/пустой/отозванный токен, подмена клиента, отсутствие прав, неверный/просроченный TLS и SAN, redirect, превышение лимита, traversal/абсолютный путь/коллизии, отказ записи/БД, параллельность и отсутствие утечек. Не обходить тесты и ACL.
